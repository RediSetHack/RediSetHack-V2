## What to build

A learner opens a Python exercise from a Stage, submits code, receives test feedback, and records an assessed coding accomplishment.

## Acceptance criteria

- [ ] Author one activity with stable identity, skill/difficulty, starter code, visible examples, hidden checks, and a completion rule.
- [ ] Execute submitted code within the verified provider boundary; never return hidden tests or expected solutions to the learner.
- [ ] Persist attempts, code under the privacy policy, error categories, elapsed-time definition, score/pass outcome, and idempotent completion/XP events.
- [ ] Wire the existing Lesson/Codelab flow to grading and review; verify wrong/correct/timeout submissions, retry-safe rewards, and another learner denial.
- [ ] Keep the slice demonstrable through its actual learner/contributor interface or existing administration/research operation; update affected contracts and use the approved behavioral test boundaries.
